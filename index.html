Trained tree

⚙ What's happening in the backend?
This is the key learning operation. fit(X_train, y_train) examines candidate feature splits and evaluates how well they separate Churn from Stay according to the selected criterion. It chooses a useful split, creates a node, then recursively searches for useful splits inside the child nodes until stopping conditions such as max_depth are reached.
Trainer voice: “This is training. The algorithm examines possible splits, chooses useful ones according to the criterion, and recursively builds the branches of the tree.”

⚙ What's happening in the backend?
A classification tree seeks child nodes that are more class-pure than the parent. With Gini impurity, the idea is Gini = 1 − Σ(pᵢ²). The algorithm evaluates possible feature/threshold combinations and chooses a split that improves the criterion. It does not literally think in English questions; the questions shown here are a visual interpretation of mathematical split rules.

In [8]:Testing — predict unseen customers
Actual test labels
[1, 0, 1, 0, 0, 1, 0, 0, 1, 0]
Predicted labels
[1, 0, 1, 1, 0, 1, 0, 0, 1, 0]
Testing = prediction on unseen data. The tree is already built. predict() follows the learned branches for each test customer and returns the predicted class.
⚙ What's happening in the backend?
For each test row, the model starts at the root and checks the learned split. It follows one branch, checks the next split, and continues until it reaches a leaf. The leaf's learned class becomes the prediction. predict() does not retrain the tree.
Trainer voice: “The model is already trained. Now each unseen customer travels through the learned branches until a leaf gives the prediction.”

Accuracy
“Out of everyone, how many predictions were correct?”
(TP + TN) / Total
Precision
“When I say CHURN, how often am I right?”
TP / (TP + FP)
Recall
“Of the customers who actually churned, how many did I catch?”
TP / (TP + FN)
Specificity
“Of the customers who actually stayed, how many did I identify correctly?”
TN / (TN + FP)
For churn: Recall can be especially important because a False Negative means a real churner was missed. Precision can also matter because retention actions cost money.
⚙ What's happening in the backend?
The metric functions use the same TP, FP, FN and TN counts from the predictions. Different metrics answer different business questions. Accuracy gives overall correctness; precision focuses on the reliability of positive predictions; recall focuses on finding actual positives; specificity focuses on correctly identifying negatives; F1 balances precision and recall.
Trainer voice: “One metric is not enough. Accuracy looks at overall correctness, precision asks how trustworthy our churn predictions are, recall asks how many actual churners we caught, and F1 balances precision and recall.”

⚙ What's happening in the backend?
The new customer's feature values are passed to the already-trained model. The same preprocessing used during training must be applied to new data. The model then follows its learned decision rules and reaches a leaf. The leaf produces the predicted class. predict() uses the model; it does not rebuild it.
Trainer voice: “Now we have a completely new customer. The trained tree is already fixed. We pass the customer's features through the learned branches and arrive at a final Churn or Stay prediction.”

⚙ Final backend explanation
The important separation is: fit() learns, predict() uses what was learned, and evaluation measures how well those predictions worked. The tree's branches are learned from training data. Testing checks those learned rules on unseen data. Only after evaluating the model do we use it to make predictions for new customers.
